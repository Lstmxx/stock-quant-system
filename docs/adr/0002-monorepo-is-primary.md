# ADR-0002：以 monorepo 应用作为主要产品路径

- 状态：已接受
- 日期：2026-07-13

## 背景

仓库同时包含 `apps/*`、`packages/*` 组成的平台，以及根目录 `scripts/` 中项目早期的独立 Python/Shell 流程。旧 README 仍以独立脚本为主，已经无法反映当前代码结构和启动方式。

如果两套路径被同等描述，维护者无法判断新功能应落在哪里，也容易误以为旧脚本与平台的数据模型、配置和依赖始终同步。

## 决策

- `apps/web`、`apps/api`、`apps/engine` 与 `packages/*` 构成主要产品和开发路径。
- 根 README、领域地图和新增架构文档以 monorepo 为准。
- 根目录 `scripts/` 定义为兼容/实验工具，不作为主平台领域边界。
- 新功能默认进入 `apps/` 或 `packages/`；只有明确服务旧流程或一次性实验时才扩展根脚本。

## 影响

- 开发者拥有单一、清晰的默认启动和演进路径。
- 旧脚本可以继续用于兼容和快速验证，但不保证与主平台同步。
- 若未来移除旧脚本，应单独评估仍在使用的兼容流程；本决策本身不要求立即删除代码。
