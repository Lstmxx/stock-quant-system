# 市场数据上下文

## 使命

为量化研究提供可重复使用的 A 股行情数据，负责采集、更新、缓存和数据可用性，不负责解释行情或作出投资判断。

## 边界

包含：

- 从行情数据源加载指定回溯区间的数据
- 全量采集、指定股票重试与定时更新
- 将价格摘要和研究数据写入 Redis 缓存
- 记录数据采集任务的进度、失败股票和结果摘要
- 管理回溯天数、并发 worker 数和采集计划

不包含：

- 因子表达式和因子有效性评估
- LLM 对股票走势的解释
- 实盘行情、订单路由或券商账户

## 核心规则

- 股票标识统一使用带市场前缀的代码，如 `sh.600000`。
- PostgreSQL 保存采集配置和任务状态；Redis 保存任务协作数据及短期行情缓存。
- 同一用户重新发起全量采集时，现有 `PENDING` 或 `RUNNING` 的采集任务会先进入取消流程。
- 失败股票重试是一个新任务，并通过 `retryOf` 保留来源任务关系。

## 术语表

| 术语 | 定义 | 避免使用 |
| --- | --- | --- |
| 行情数据 | 用于研究的股票价格、成交量及派生矩阵 | 实盘行情（除非确实是实时数据） |
| 数据采集任务 | 异步获取或刷新行情数据的任务，类型为 `DATA_COLLECTION` | 同步抓取作业 |
| 回溯天数 | 单次采集需要覆盖的历史区间，默认 250 天 | 训练周期 |
| 失败股票 | 一次采集任务中未成功更新的股票代码集合 | 无效股票 |
| 价格摘要 | 为分析流程缓存的近期价格统计，不是完整行情集 | 分析报告 |

## 协作关系

- 向**因子研究**提供因子计算所需的行情矩阵。
- 向**投研决策**提供个股价格摘要；缓存未命中时接受补数请求。
- 依赖**平台运行**创建任务、传递取消信号和持久化状态。

## 代码地图

- 采集与缓存：`apps/engine/app/core/data_loader.py`
- 调度：`apps/engine/app/scheduler.py`
- 内部补数接口：`apps/engine/app/routers/internal.py`
- 任务编排：`apps/api/src/modules/task`
- 数据管理界面：`apps/web/src/features/data`
- 数据采集配置：`packages/database/src/schema.ts` 中的 `dataCollectionConfigs`
