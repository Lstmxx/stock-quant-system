# 修复因子模块可靠性与体验

## Goal

让因子挖掘从配置、入队、执行、取消、日志到因子持久化形成可信闭环，并让有效因子可被后续选股与 LLM 个股分析消费：任务状态必须反映真实执行结果，因子数据严格按用户隔离，界面输入与 Engine 实际语义一致，失败时保留上下文并给出可操作反馈。

## Background

- 因子研究上下文定义当前能力为全市场量价因子研究，研究输入是“研究方向”，因子和任务均归属于发起用户。
- 产品主要用途已确认：有效因子用于全市场选股，并作为量化上下文加入后续 LLM 个股分析。
- 当前 Web 将 `targetSymbol` 展示为股票代码，但 Worker 把它传给 `AlphaMiner.mine(direction=...)`，不存在单标的数据筛选链路。
- Engine 已有未接入主流程的 `MultiFactorSelector` 雏形；当前 LLM 个股分析只传递因子表达式、历史 IC、ICIR 和方向，没有计算目标股票的最新因子值、横截面排名或综合得分。
- `AlphaMiner` 调用不存在的 `FactorLibrary.get_all()`；轮次异常被吞掉后，Worker 仍可能把任务标记为 `COMPLETED`。
- FactorLibrary、EvolutionStrategy 与 AlphaMiner 混用了字符串、字典和对象契约；12 位表达式哈希也不符合数据库 UUID 主键。
- 因子去重与进化查询未按用户过滤；IC/ICIR 等指标以文本存储和排序。
- 创建失败仍关闭弹窗；取消只在任务开始前和全部计算结束后检查；日志定时轮询允许请求重叠和跨任务迟到响应。
- 当前相关测试没有覆盖挖掘主循环、进化、持久化、用户隔离、协作式取消或日志竞态。

## Requirements

### R1. 统一研究输入语义

- Web、API、任务参数、Worker 和结果摘要使用同一个领域名称。
- 不得再把研究方向展示或命名为股票代码。
- 输入必须来自明确的受支持研究方向集合，或经过等价的服务端校验。
- 研究方向只约束因子发现的经济学假设，不约束后续选股股票池，也不替代个股分析中的股票代码。

### R2. 统一因子领域契约

- FactorLibrary 的新增、查询、有效因子读取和进化输入使用一致的类型契约。
- AlphaMiner 不得调用不存在的方法，也不得依赖字典/对象混用。
- 表达式去重按用户作用域执行；两个用户允许拥有相同表达式。
- 因子主键符合数据库类型；表达式唯一性由独立约束表达。
- 只有完成评估且通过标准的候选因子可持久化为有效因子。

### R3. 可信任务状态与队列

- 任一挖掘轮次或持久化关键步骤失败时，任务不得报告成功。
- 创建任务在数据库记录和 Redis 入队部分失败时不得留下永久 `PENDING` 假任务。
- 队列保持先入先出。
- 取消是协作式的：至少在轮次、候选因子和昂贵 LLM/计算步骤之间检查，并区分“正在取消”与“已取消”的用户反馈。

### R4. 严格用户隔离与数值语义

- 因子查询、去重、有效因子读取、进化与保存全部限定当前用户。
- 因子指标使用可正确比较和排序的数值数据库类型。
- 列表分页参数必须有整数、非负和最大页大小约束。

### R5. 稳定日志与前端交互

- 同一任务最多存在一个进行中的日志请求；切换/关闭任务后迟到响应不得写入当前日志。
- 任务终态后停止轮询，并向用户展示日志加载失败状态。
- 创建任务失败时保留表单并保持弹窗打开；成功时才清空关闭。
- 配置加载、保存、列表加载和取消异常提供用户可见反馈。
- 任务列表展示中文状态、失败原因或结果摘要；因子方向对缺失/零值使用中性展示。
- 修复因子页面的 TypeScript 构建错误和 Ant Design 已弃用 API。

### R6. 回归保护

- 增加挖掘主循环成功、失败和取消测试。
- 增加 FactorLibrary 用户隔离、去重、UUID/持久化契约及进化输入测试。
- 增加 API 参数校验、数值排序、入队失败和 FIFO 行为测试。
- 增加创建弹窗失败不关闭、日志无重叠/无串流和终态停止轮询测试。

### R7. 选股与个股分析桥接

- 修复并复用现有多因子选股逻辑，基于当前用户的有效因子和最新全市场行情计算横截面因子暴露。
- 选股结果至少包含股票代码、综合得分、排名以及参与计算的因子明细。
- 对单只股票生成可供 LLM 消费的因子上下文，至少包含实际因子值、横截面排名或百分位、因子方向和综合得分。
- 现有 LLM 个股分析自动使用上述目标股票因子上下文，不再仅传递因子表达式和历史 IC/ICIR。
- 因子计算、方向调整和权重逻辑在选股与个股分析之间必须复用，避免两个消费者产生不同结论。
- 缓存或任务执行方式必须避免每次页面刷新和分析轮询重复执行全市场因子计算。
- 默认因子集合按质量自动选择前 5 个有效因子；不足 5 个时使用全部有效因子。
- 用户可以手工选择有效因子覆盖默认集合；该选择同时作用于选股与 LLM 个股分析。
- 自动质量排序至少综合有效状态、IC 绝对值和 ICIR，并使用确定性的并列排序规则。
- 选股由用户手工触发为异步任务；挖掘完成后不得自动消耗资源运行选股。
- 成功结果按用户、交易日和规范化因子集合缓存或持久化；页面刷新读取最近结果。
- LLM 个股分析优先复用当天相同因子集合的成功结果；不存在时最多自动触发一次计算并等待完成。
- 因子集合变化后，旧结果必须标记为过期且不得被当作当前结果静默使用。
- 股票池支持 `ALL_MARKET`（默认，使用已采集且数据有效的全市场股票）和 `WATCHLIST`（仅当前用户自选股）两种模式。
- 股票池类型和实际股票集合必须固化到任务快照；自选股模式不得读取其他用户的股票。
- 增加独立的“因子选股”任务历史页面；每次选股运行创建一条不可覆盖的任务记录。
- 选股任务列表至少展示创建时间、数据日期、状态、因子数量/集合摘要、Top N 参数和失败原因或结果摘要。
- 每条成功任务提供“查看”操作；弹窗展示该次任务的 Top N 股票，包括代码、综合得分、排名和各因子贡献。
- 因子列表负责选择/取消选择选股因子，并提供进入选股任务页面的入口；选股任务页面负责发起、跟踪和查看结果。

## Acceptance Criteria

- [ ] AC1: 发起一次受支持方向的挖掘任务后，至少会进入评估流程；不存在 `get_all` 或类型契约运行时错误。
- [ ] AC2: 任务只有在完整执行成功后进入 `COMPLETED`；关键步骤失败进入 `FAILED` 并保留可读原因。
- [ ] AC3: 用户 A 和用户 B 可以保存相同表达式，且彼此的因子不会参与对方的去重、进化或列表结果。
- [ ] AC4: 因子 ID 可写入 UUID 列，IC 排序遵循数值顺序。
- [ ] AC5: 队列按创建顺序消费；Redis 入队失败不会留下不可恢复的 `PENDING` 任务。
- [ ] AC6: 取消请求会在下一个协作检查点停止剩余挖掘工作，界面不会提前宣称已经完全终止。
- [ ] AC7: 创建失败时弹窗保持打开且输入保留；成功时关闭并刷新任务列表。
- [ ] AC8: 日志轮询不会并发重叠、重复追加或把旧任务日志追加到新任务，并在终态停止。
- [ ] AC9: 因子相关 Web/API/Engine 测试通过；因子页面不再产生 TypeScript 或 antd lint 错误。
- [ ] AC10: 数据库迁移可向前应用，并有明确回滚或兼容说明。
- [ ] AC11: 用户可以获得 Top N 选股结果及因子贡献明细，结果只使用自己的有效因子。
- [ ] AC12: LLM 个股分析提示词包含目标股票的实际因子值、横截面位置、方向和综合得分，并与同一时点选股结果一致。
- [ ] AC13: 每次运行选股都会新增一条可追溯任务；历史任务结果不会被后续运行覆盖，用户可从任务行打开 Top N 结果弹窗。
- [ ] AC14: 全市场与自选股两种股票池均可运行；自选股结果只包含任务创建时当前用户的自选股快照。

## Out of Scope

- 单股票专用的时序因子研究模型。
- 重新设计 DSL、指标阈值或 LLM 提示词质量。
- 将 Redis 队列整体替换为新的消息系统。
- 重做整个应用的视觉设计或处理与因子模块无关的构建错误。
