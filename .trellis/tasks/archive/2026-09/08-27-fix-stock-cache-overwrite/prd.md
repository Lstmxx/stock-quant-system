# 修复股票数据缓存覆盖与重复行情聚合

## Goal

修复股票数据采集完成后因 `date + code` 重复导致的聚合失败，并让单股 Redis 行情缓存以稳定 key 保存，使成功拉取的新数据覆盖旧数据而不因每天日期变化持续累积历史 key。

## Requirements

- 仅修改 Engine 数据加载链路及其测试，不改变 API/前端任务状态契约。
- 单股行情缓存使用不随日期范围变化的 key（`kline:{code}`）；成功拉取后覆盖该股票旧缓存，并保留现有过期策略。
- 读取单股缓存时兼容当前日期范围 key，避免已有部署缓存立即失效；成功读取或新拉取的数据应按股票代码合并。
- 股票代码列表去重，避免同一股票被重复分配或重复读取。
- 构建宽表前将行情记录按 `date + code` 去重，保留最后一条有效记录，保证 `DataFrame.pivot()` 不因重复索引失败。
- 聚合行情缓存继续使用临时 key + 原子替换，确保新聚合数据完整写入后覆盖旧聚合缓存。
- 为缓存 key 迁移、重复记录处理和“新数据覆盖旧数据”增加确定性单元测试。

## Acceptance Criteria

- [x] 相同股票的新一批行情写入后，读取 `kline:{code}` 得到新数据，不产生按日期范围增长的永久 key 集合。
- [x] 输入股票列表含重复代码时，只产生一份该股票行情，且不会触发 `pivot()` 重复索引异常。
- [x] 输入数据含相同 `date + code` 的多条记录时，聚合结果只保留最后一条有效记录。
- [x] 现有日期范围格式的单股缓存仍可被读取，迁移期间不会因缓存格式变化导致全量数据缺失。
- [x] 相关 Engine 测试通过，且工作区没有由本任务引入的格式错误。

## Constraints

- 不删除或覆盖与本任务无关的工作区改动。
- 本任务不负责清理已经存在的旧日期范围 key；新逻辑通过 TTL 自然回收，必要的运维清理另行处理。
