# 优化全局数据采集设置定时规则输入

## 目标

将全局数据采集设置中的定时规则输入优化为可视化的时间选择控件，降低用户填写 APScheduler cron 规则的认知和输入成本，同时保持现有后端配置契约不变。

## 已确认事实

- 目标页面位于 `apps/web` 的数据管理功能。
- 全局配置接口仍使用 `cronExpression` 字段，当前默认规则为 `0 20 * * mon-fri`。
- 后端要求 cron 表达式包含五个有效 APScheduler 字段，调度时区为 `Asia/Shanghai`。
- 本次需求明确要求使用 Ant Design `TimePicker` 优化定时规则输入。

## 需求

1. 定时规则的小时、分钟应通过 `TimePicker` 选择，不再要求用户直接输入完整 cron 表达式。
2. 保存配置时，将选择的时间转换为现有接口需要的 cron 表达式格式，并保留工作日定时语义（`0 <minute> <hour> * * mon-fri`）。
3. 编辑已有配置时，应能从现有 cron 表达式解析并回显小时、分钟；无法解析时使用页面现有默认时间，不阻塞页面渲染。
4. 其他配置项、保存行为、接口字段和数据采集流程保持不变。
5. 控件应符合现有页面的表单布局与可用性要求，并在项目已有测试/构建门禁下通过。

## 验收标准

- [x] 全局数据采集设置中显示 `TimePicker`，用户可选择小时和分钟。
- [x] 保存时发送的 `cronExpression` 仍为五字段工作日 cron，且时间与选择结果一致。
- [x] 已有合法 cron 配置打开页面时，TimePicker 显示对应时间。
- [x] 非法或无法解析的 cron 不导致页面崩溃，并使用安全默认时间。
- [x] `lookbackDays`、`workerCount` 及其他数据采集行为无回归。
- [x] 相关前端类型检查/构建与 `git diff --check` 通过。

## 范围外

- 不修改 API、Engine、数据库或调度器的 cron 契约。
- 不增加自定义日期、频率或工作日选择器；本次固定保留现有工作日规则。
