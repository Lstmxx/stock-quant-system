# Automated Testing Loop Design

Status: Draft pending user confirmation of the live-data gate policy.

## 1. Design Goals

- Give developers, AI agents, and CI one consistent set of verification commands.
- Prove critical behavior across real project boundaries, not only mocked modules.
- Keep pull-request results deterministic and fast enough for iterative AI development.
- Detect external Baostock drift without confusing provider outages with product regressions.
- Preserve useful failure evidence: process logs, Playwright report, screenshots, and traces.
- Make the required gate proportional to the changed behavior while keeping a full gate available.

## 2. Proposed Test Architecture

```text
Feature implementation
        |
        v
Fast deterministic gate
  lint + type/build + Bun/Vitest/Pytest
        |
        v
Full-stack deterministic gate
  ephemeral PostgreSQL + Redis
        |
  real API + real Engine + real Web
        |
  fixture market provider + local fake LLM
        |
  Playwright critical user journeys
        |
        v
Trellis completion gate / required PR checks

Separate schedule/manual lane
  bounded real Baostock canary
  optional full collection exercise
  no paid LLM calls by default
```

## 3. Test Matrix

| Layer | Purpose | Data/dependencies | Trigger | Initial target |
| --- | --- | --- | --- | --- |
| Static/build | Compile, lint, configuration, Ant Design accessibility | No external services | Every implementation iteration / PR | Under 2 minutes |
| Unit/contract | Domain rules and boundary schemas through public interfaces | In-memory fakes and fixed vectors | Every implementation iteration / PR | Current full suite; no path optimization yet |
| Service integration | API/Engine behavior against real PostgreSQL and Redis | Disposable test infrastructure; external providers fake | PR for backend/database/cross-layer changes | Under 3 minutes |
| Playwright smoke | User-visible critical paths across the real app stack | Same deterministic full-stack environment | UI/cross-layer task completion and required PR check | Chromium, one worker, under 5 minutes |
| Playwright regression | Wider workflow/error matrix | Deterministic full-stack environment | Default-branch push or nightly | Add browsers/shards only after isolation |
| Live provider canary | Detect Baostock login/schema/freshness drift | Real Baostock; isolated cache | Nightly and `workflow_dispatch` | Bounded symbols/date range, under 3 minutes |
| Full live collection | Exercise the true long-running collection lifecycle | Real Baostock, PostgreSQL, Redis | Manual or weekly | Explicit 20+ minute budget |

## 4. Environment and Lifecycle

### Shared deterministic environment

- Add a test-only Compose file for PostgreSQL 15 and Redis 7 with health checks, no persistent host volumes, and test-specific ports/database names.
- Use one repository-owned orchestration command for both local agents and GitHub Actions:
  1. start/await infrastructure;
  2. migrate a fresh test database;
  3. start Engine, API, and Web with test environment variables;
  4. create/seed test identities and domain fixtures;
  5. run Playwright;
  6. capture artifacts and always tear down in `finally`.
- Do not read the developer `.env` implicitly for E2E. Use committed non-secret defaults plus an ignored local override. Test secrets must be synthetic and distinct from development/production values.
- CI sets `reuseExistingServer: false`; local mode may reuse explicitly requested application servers, but the default automated gate starts its own isolated stack.

### External provider seams

- Introduce a project-owned market-data provider interface. Production selects Baostock; deterministic tests select a checked-in fixture provider containing a small, coherent multi-symbol trading dataset.
- Keep expected factor/selection values independent from production calculations. Golden assertions must be literals or hand-worked examples, not values regenerated by the same code under test.
- Run a local OpenAI-compatible stub for LLM browser flows. Seed the Web/API with a model pointing to that stub under test-only private-URL allowance. Responses cover success, invalid JSON, timeout, and partial failure without paid calls.
- Browser request interception must not mock first-party `/api/*` routes in full-stack tests. It is acceptable only for browser-owned third-party resources that the product does not control.

### Database, Redis, and identity isolation

- Recreate the disposable infrastructure for each full E2E run initially; use one Playwright worker until server-side isolation is proven.
- Cover sign-up/sign-in through the UI in one dedicated authentication journey.
- Other tests may create users through the public auth API and reuse generated `storageState`; auth files live only in Playwright output and remain ignored.
- Generate unique user emails and task identifiers from the run/test ID. Never depend on another spec's side effects or execution order.
- When parallelism is introduced, allocate one account and isolated domain records per worker. Redis key namespacing or per-worker Redis instances must be solved before increasing worker count.

## 5. Initial Playwright Journeys

### MVP blocking journeys

1. **Authentication and routing** — unauthenticated access redirects to `/login`; sign-up reaches `/data`; reload preserves the session; unknown routes converge on `/data`.
2. **Global data collection** — authenticated user reads/updates global configuration, starts a fixture-backed collection, observes active-state duplicate prevention, then sees a terminal result and task details.
3. **LLM model management** — user creates an OpenAI-compatible test model, tests the connection against the local stub, sets it as default, edits key semantics safely, and sees actionable failures.
4. **One asynchronous research tracer** — seed fixed market/factor inputs, create either a factor-selection or LLM-selection task, observe polling/terminal status, and inspect persisted result evidence.

### Follow-up regression journeys

- Cooperative cancellation and retry for collection/mining/LLM selection.
- Factor library manual/AUTO selection and Top N evidence.
- LLM stock-selection partial success, failed-candidate detail, and retry from frozen snapshot.
- Cross-user access isolation and active-task conflict behavior.
- Accessible keyboard/role behavior for Ant Design Modal, Table, Drawer, Popconfirm, and row actions.

## 6. Playwright Configuration Contract

- Root `playwright.config.ts`, root-owned `tests/e2e/`, and root dev dependency on `@playwright/test`.
- Chromium only for the blocking MVP. Firefox/WebKit run later on default-branch/nightly regression if value justifies cost.
- `forbidOnly: true` and `failOnFlakyTests: true` in CI.
- `retries: 1` in CI, `0` locally; a retry is diagnostic, not a green escape hatch.
- `workers: 1` initially because current workflows share global collection state and fixed Redis keys.
- `trace: 'on-first-retry'`, screenshot on failure, and retained video only on failure.
- HTML plus CI-native/blob or JUnit reporting; upload reports, traces, application logs, and failed screenshots with short retention.
- Prefer `getByRole`, `getByLabel`, and visible domain text. Add `data-testid` only where a stable accessible contract cannot distinguish repeated Ant Design controls.
- Use web-first assertions and domain-state polling; forbid fixed sleeps as synchronization.

## 7. Command and Gate Contract

Proposed stable root commands (names may be adjusted during implementation, semantics must remain):

- `bun run test:unit` — all Bun, Vitest, and Pytest suites excluding live tests.
- `bun run test:build` — Web/API builds, Ruff, and Ant Design lint.
- `bun run test:integration` — real PostgreSQL/Redis service integration.
- `bun run test:e2e` — deterministic full-stack Playwright smoke suite.
- `bun run test:live:data` — bounded real Baostock canary, opt-in.
- `bun run verify:fast` — build/static + unit/contract gate.
- `bun run verify:full` — fast + integration + deterministic Playwright gate.

Trellis integration:

- Every PRD acceptance criterion identifies its required test layer or records why automated coverage is not applicable.
- `implement.md` lists exact validation commands before implementation is activated.
- A shared `.trellis/spec/guides/automated-testing.md` maps changed layers to required commands.
- `trellis-check` must execute the mapped root command and report artifact paths; a task cannot be described as complete after only code inspection.
- Web-visible or cross-layer behavior requires Playwright evidence. Pure logic changes may remain at unit/integration level when the PRD explicitly says no user journey changed.
- CI required checks are the remote authority; the local full gate is the pre-commit/pre-handoff equivalent.

## 8. GitHub Actions Shape

### Required pull-request workflow

- Install pinned Bun and Python/uv dependencies from lockfiles.
- Run `verify:fast` first.
- Start disposable PostgreSQL/Redis with health checks, migrate/seed, install Chromium only, and run deterministic Playwright smoke.
- Upload Playwright/report/process artifacts even on failure.
- Add hard timeouts and concurrency cancellation for superseded branch runs.
- Configure branch protection to require the fast and deterministic E2E jobs.

### Live-data workflow

- Trigger with `schedule` and `workflow_dispatch`; use concurrency `1` to avoid Baostock session interference.
- Start isolated Redis/database resources and force cache bypass.
- Run a bounded provider canary nightly; run full collection manually or on a less frequent schedule.
- Publish a structured summary that distinguishes product assertion failure, provider unavailability, timeout, and rate/session errors.
- Recommended initial policy: visible failing workflow/notification but not a required PR status check.

## 9. Compatibility, Security, and Operations

- Test configuration must never fall back to development or production database URLs.
- Synthetic encryption/auth/internal-service secrets are committed only as test-safe values; real keys remain in CI secrets.
- Never upload authenticated storage state. Treat traces and logs as sensitive and use short artifact retention.
- The full-stack fake modes are enabled only through explicit test environment values and fail closed outside test execution.
- Cleanup is idempotent so interrupted AI runs do not leave containers, ports, or queues blocking the next run.
- Rollback is additive: remove new workflows/scripts/config and keep existing package tests unchanged. Provider seams must preserve the production Baostock/LiteLLM default.
