# 全项目架构与体验审查

## Goal

对当前 monorepo 主产品路径进行一次基于代码证据的全项目审查，识别会影响正确性、可靠性、安全性、可维护性、性能和用户体验的问题，并输出可以直接进入后续修复任务的优先级清单。

本阶段将按审查报告实施修复，并补充回归验证；Dashboard 现有页面及其入口将移除，后续新版 Dashboard 另立需求。

## Background

- 主产品路径由 `apps/web`、`apps/api`、`apps/engine` 和 `packages/database` 组成。
- Web 使用 React、Vite 和 Ant Design；API 使用 Bun、Elysia、Better Auth 和 Drizzle；Engine 使用 FastAPI、Redis、PostgreSQL 和 Python 量化计算栈。
- PostgreSQL 是持久化业务状态的事实来源；Redis 用于任务队列、短期缓存、日志和取消信号。
- 核心业务覆盖市场数据采集、因子研究、LLM 配置与调用、LLM 选股、策略/分析和异步任务管理。
- `scripts/` 属于兼容或实验路径，不是主产品边界，但其依赖、配置和数据写入方式可能形成运维或数据风险。
- 仓库已有若干跨层工作流契约，但多数通用编码规范索引仍处于 `To fill` 状态。

## Requirements

### R1. 架构与边界

- 审查部署单元、领域上下文、模块职责、依赖方向和共享基础设施边界。
- 检查 Web、API、Engine、PostgreSQL、Redis 之间是否存在职责泄漏、重复事实来源或紧耦合。
- 检查 monorepo 主路径与遗留脚本之间的能力重复和配置漂移风险。

### R2. 跨层正确性与隐藏缺陷

- 沿市场数据、因子、LLM、LLM 选股和任务管理链路追踪请求、队列、状态、结果和错误。
- 检查用户隔离、认证授权、内部接口信任边界、并发竞争、幂等性、取消、重试、超时和部分失败。
- 检查数据库约束、迁移、Redis 状态与 PostgreSQL 状态是否可能分叉。
- 每个高优先级发现必须给出实际文件和行号证据，避免只给抽象建议。

### R3. 功能与性能优化

- 检查重复查询、无界读取、轮询/SSE、缓存策略、批处理、外部数据源和 LLM 调用的成本与延迟风险。
- 识别功能缺口、不可恢复流程、重复实现和可以简化的工作流。
- 区分立即修复项、结构性改造项和可选增强项。

### R4. 用户体验

- 审查导航、信息架构、表单、表格、模态框、加载/空/错误/成功状态和长任务反馈。
- 检查取消、重试、失败详情、配置缺失、权限失效以及移动/窄屏场景。
- 检查基本可访问性，包括可见标签、键盘操作、焦点、颜色依赖和危险操作确认。

### R5. 工程质量与可运营性

- 审查类型安全、输入验证、错误处理、日志、敏感信息、配置管理和依赖边界。
- 运行仓库已有的构建、类型检查、测试和 lint，并区分代码缺陷与环境依赖失败。
- 评估测试覆盖的关键空白、容易产生伪通过的测试以及缺失的集成/契约测试。

### R6. 交付报告

- 按 P0/P1/P2/P3 标记严重度，并说明影响、触发条件、证据和建议。
- 对误报风险高的发现进行代码路径复核；关键结论不得仅依赖静态模式匹配。
- 提供按收益、风险和依赖排序的短期、中期优化路线。

### R7. 修复范围

- 修复报告中的 P1/P2 问题，并对可安全落地的 P3 工程治理项同步处理。
- 移除现有 Dashboard 页面、路由入口和导航入口，不在本任务设计新版 Dashboard。
- 为修复项补充回归测试、契约校验和必要的迁移。

## Acceptance Criteria

- [x] 覆盖 `apps/web`、`apps/api`、`apps/engine`、`packages/database`、根级运行配置和主产品相关文档。
- [x] 至少建立一份端到端系统/数据流地图，并用它验证主要跨层契约。
- [x] 每个 P0/P1 问题包含可复核的文件与行号、用户或系统影响、触发方式和修复方向。
- [x] 报告分别覆盖架构、功能/性能、隐藏缺陷、用户体验、测试/运维五个方面；无发现的方面也明确说明检查范围。
- [x] 执行可用的 Bun/TypeScript、Web/Vitest 和 Engine/Pytest/Ruff 检查，并记录未执行或失败的环境原因。
- [x] 将已确认缺陷与推测性改进分开，不把偏好性重构描述成确定 bug。
- [x] 最终输出包含问题摘要、详细发现、快速收益项、结构性改造项和建议实施顺序。
- [x] 现有 Dashboard 页面及其导航入口已移除；访问旧路径有明确跳转或 404 行为。
- [x] 报告中的已实施问题均有对应测试或验证记录，未修复项明确列出原因。

## Out of Scope

- 不设计或实现新版 Dashboard；新版 Dashboard 另行规划。
- 不评估券商接入、实盘交易、资金/仓位管理或生产级交易风控，因为这些不属于当前产品边界。
- 不对外部行情或 LLM 服务本身做供应商级安全审计。
- 不以根目录实验脚本作为主产品质量基线，但会报告它们对主系统造成的漂移或误用风险。

## Technical Notes

- 审查基线为当前 `refactor` 分支工作树；任务规划文件属于本次审查产生的预期变更。
- 现有工作流契约是审查依据；通用规范文档缺失本身可作为治理类发现，但不能据此虚构项目约定。

## Notes

- Lightweight tasks can remain PRD-only.
- For complex tasks, add `design.md` for technical design and `implement.md` for execution planning before `task.py start`.
